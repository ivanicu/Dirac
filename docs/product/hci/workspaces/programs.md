# Programs Projection Brief

**Status:** normative design; not implementation-complete

## Human question

What are we trying to learn, what work and evidence bear on it, what is blocked,
and which accountable decision is next?

## Entry profiles and cost

Program lead (daily, decision authority, high portfolio error cost), project
operator (continuous, scheduling authority), executive/reviewer (episodic,
read-mostly, restricted disclosure), external collaborator (scoped).

## Primary projection

Program opens as a question map with a compact evidence/readiness summary. The
same WorkThread graph can project as next-actions, dependency graph,
timeline/Gantt with uncertainty, board, decision log, and stage-gate view.
Critical path is a range with confidence/source, never false precision.

## Semantic inputs and actions

Inputs: Program version, WorkThreads, questions, objectives, hypotheses, work
nodes/edges, evidence, decisions, milestones, memberships, permission envelope.
Actions: frame/revise question, split/merge/fan work, delegate, link canonical
objects, assess criteria, record/supersede decisions, offer/accept handoffs.
Program readiness is derived from versioned gate criteria and evidence freshness.

## Failure and scale

Concurrent edits use field merge only for safe metadata; conclusions and
decisions append/supersede. Unauthorized graph nodes do not leak through counts
or layout gaps. At scale the server returns permission-safe summaries and
windowed subgraphs. Empty state begins with a question/template, not an ID form.

## Acceptance witness

Create a question, branch three dependent nodes, merge evidence, show uncertain
critical path, delegate one node, revoke a viewer, and record a gate decision
with accountable actor and source versions.
